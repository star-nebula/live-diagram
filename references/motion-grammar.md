# 动法（motion grammar）

一种图的定义：**图是运行中系统的监控面板**。版面固定，动的全是系统状态。任何一帧截出来都是完整可读的图——第 0 帧和第 600 帧一样好。

## 1. 版面永远不动

- 一张固定画布。盒子、标题、图例、说明文字不移动、不出现、不消失。
- 没有镜头运动、没有开场动画、没有一步步 reveal、没有交互、没有旁白。
- 颜色是小代码：几种角色色 + 灰/白，图例说明颜色→角色。
- terminal-dark 主题把盒子画成文本模式框（上下实线、两侧分段线），全部等宽字体。

## 2. 三种节奏同时跑

面板显得"活"，是因为三层运动叠加且**互相印证**，不是哪个特效炫：

**快（每帧或每秒内变化）**
- 光点：主流的每条线上常有点在跑——大点带小尾点。多条线同时有点，流出、汇入，各自 period 与 offset 错开，永不整齐划一。
- 转圈符（`◐◓◑◒`）标出正在干活的单元，各有相位。
- 快计数器（速率、累计 token）在两处出现（盒子里 + 状态栏），数字永远一致——它们引用同一个变量。

**中（每 1–3 秒一变）**
- 日志：固定行数，新行推进；最新一行亮且粗，旧行灰。角色名保持角色色。
- 仪表条每隔几秒重掷数值；越过阈值时条变色、标签翻词、图例同步。
- 工位在 `转圈干活 ⇄ ✓ 完成` 间翻转，各有周期。

**慢（每 3–5 秒一变，且累积）**
- 侧栏告警台：固定顺序一次亮一个——`◇` 变 `◆`、行高亮加粗、它指向目标的虚线光束变色并携带光点；亮约 3 秒，静默 1.5 秒，轮下一个。
- 亮起期间，"处置建议"逐字打出。
- 每轮一次的累计：处置次数 +1、tokens 增长。

## 3. 处处一个事实（one truth）

把面板当一篇报道读，数字必须互相对得上：

- 日志里那行 `GPU 负载 0.92 拥塞` 出现时，条上就是 0.92、标签就是"拥塞"。
- 日志说"限流保护 触发"时，侧栏亮着的正是"限流保护"，状态正是"处置中"。
- 状态栏的 tokens 和守卫模块里的 tokens 是同一个数。

机制保证：**日志不手写**。每个状态机（gauge、alarm、worker、cycle）在状态变化时产出自己的日志行，值取自它当时的变量。凡是屏幕上别处已有的东西，绝不为它另写日志文案。

## 4. 没有真数据就说"示意"

不接真实数据的面板就是模拟。规矩：

- 固定事实（报告里的数、模型名）是静态文本，并在画面可读处（`credit` 行）或帖文里注明来源。
- 凡因动画而动的量（packets、calls、速率计数）都是动画自身的状态，画面上标 `示意 / illustrative`。
- 绝不编造一个测量值让它看起来像真的。复刻别人的图，必须标注"复刻"并署名原作者。

## 5. 同一套动法用在浅色信息图上

白底粉彩信息图（小红书风）保留上述每一条规则，只换表达，不换原则：

- **颜色与结构尊重原图**。别把粉彩图改成暗色终端；盒子保留原有填充与描边，"激活"表现为更粗的描边加柔光，而不是换底色。
- **一条主时间线**。用一个 `cycle` 状态机定义"系统此刻在干嘛"（步骤 1..5、reflect、output…），屏幕上一切亮起的东西都从它推导——步骤 3 亮时，对应工具行亮、对应箭头变色并带光点。
- **三种节奏放温柔**。快：小光点沿箭头漂移；中：内环轮转；慢：计划步骤推进、记忆环路每轮各亮一次。
- **有含义的箭头**才在状态说它在使用时变色加粗带双点；纯结构箭头保持灰色带微弱点。
- **不加模块**。复刻别人的信息图就用他的模块、措辞、颜色；不加自己的注释和计数器。画面上署名原作者。

## 6. 确定性

时间唯一输入：`state = f(t)`；"随机" = `hash(种子, 序号)`。不读墙钟、不用 `Math.random()`、不用 CSS 动画。因此帧可复现，检查器可以跳到任意 t 重画并逐字节比对。
